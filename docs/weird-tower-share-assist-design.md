## 1. 概念与关系模型

| 概念 | 含义 | 额度（每周期） |
| --- | --- | --- |
| **接受助力角色**（receiver） | 它的助力码被别人使用，从而「被助力」 | 最多被 3 次 |
| **助力角色池**（assist pool） | 可发起助力的角色来源 | 每个角色最多发起 1 次 |
| 关系 | receiver 有 3 个槽位，每槽指向池内 1 个角色 | — |

两条核心约束（决定整个数据模型）：

1. **两者可以重叠** —— 同一个角色既能被助力、也能去助力别人。
2. **一个助力者只能占一个槽位** —— 因为每角色每周期只能发起 1 次助力。
   这是一条**全局唯一约束**，不是「每个 receiver 内部唯一」。

关系是**低频变化**的，所以**持久化跨周期保留**；而「本周期谁已经用掉了额度」是**每周期重置**的，必须分开存。

> 为什么保留手动渠道（master 的说明）：**爬塔进度不同的角色助力效果不同**，所以不能纯自动分配——
> 需要人工按收益把关键角色指定到关键位置。

## 2. 数据模型

### 2.1 持久关系（跨周期保留）

localStorage key 建议 `weirdTowerAssistPlan`：

```json
{
  "version": 1,
  "receivers": [
    {
      "key": "9724:130301444",
      "name": "世界国皇帝",
      "server": "9724服",
      "mode": "manual",
      "slots": ["26501:666543015", null, null]
    }
  ],
  "assistPool": ["9738:139075590", "9724:130301444"],
  "updatedAt": "2026-09-18T01:40:00.000Z"
}
```

- **`key` 用项目已有的稳定身份键** `getStableTokenKey(serverId, roleId)` = `"<serverId>:<roleId>"`
  （`src/utils/token.ts`；`tokenGroups` 也用它，保持一致）。
  → 重新导入 token、tokenId 变化时关系**不会丢**。
  ⚠️ 若某 token 缺 `serverId`/`roleId`，`getStableTokenKey` 返回 `null` → 该角色无法持久化，UI 需明确提示。
- `name` / `server` 只用于展示（冗余存储，避免 token 被删后列表变成一堆 ID）。
- `mode`：`"manual"` | `"auto"`（角色级，见 §4）。
- `slots`：固定长度 3，允许 `null`（空槽）。
- `assistPool`：一维数组，顺序即展示顺序（也是自动分配的候选顺序）。

### 2.2 本周期执行状态（按周期键重置）

```json
{
  "cycleKey": "13",
  "usedInitiators": ["26501:666543015"],
  "fullReceivers": ["9738:139075590"]
}
```

- `cycleKey` = 活动周期序号（见 §6），**换周期即整批作废**。
- `usedInitiators`：已收到 `12200100`（自己已用过机会）的角色 → 本周期不再派发。
- `fullReceivers`：已收到 `12200090`（目标已满 3 次）的**目标角色** → 本周期不再尝试。

## 4. 助力界面（独立弹窗）

**入口：批量日常页 →「怪异塔」栏目 →「打开助力界面」按钮**（2026-09-18 调整，见 §4.0）。

最早是挂在 `GameStatus`「日常」分区的一张卡片，但实测它是那里的第 5 张卡（文档纵向 1002px，
刚好落在首屏之外），master 反馈找不到 —— **发现性太差，改成从批量页按钮打开的弹窗**
（复用该文件既有的 `n-modal` 写法，不动两栏布局）。

### 4.0 弹窗实现要点

- `<n-modal preset="card" title="怪异塔助力" style="width: 1100px; max-width: 94vw">`，
  内容外再裹一层 `max-height: 76vh; overflow: auto`，避免小屏顶出屏幕。
- **必须用 `display-directive="show"`**：默认 `"if"` 会在关闭时销毁内容，
  执行日志与进行中的状态就丢了。
- 卡片组件加 **`embedded` 属性**：为 true 时去掉自带的白底 / 阴影 / 圆角 / 内边距
  （弹窗自带卡片外观，否则"卡片套卡片"），并隐藏自己的 `h3`、把滚动区放高。
- 关掉弹窗不影响正在跑的助力任务（组件常驻，异步流程继续，日志保留）。

### 4.1 界面内容

```
┌─ 怪异塔助力 ─────────────────────────────────────────────┐
│ 周期 #13 招募周：助力只在黑市周开放          [非黑市周]   │
│ 自动分配  开始助力（n）   助力池 N 个角色 · 已分配 M 个槽位 │
├──────────────────┬───────────────────────────────────────┤
│ 接受助力角色 (8)  │  世界国皇帝 @9724服      [手动指定 ▾]  │
│ ────────────────  │  ───────────────────────────────────  │
│ 世界国皇帝  2/3 ▶ │  槽1  海王 @26501服           [更换]   │
│ 38号战士    0/3   │  槽2  未指定（自动）          [指定]   │
│ …                │  槽3  未指定                  [指定]   │
└──────────────────┴───────────────────────────────────────┘
```

- **左：接受助力角色列表**（只显示 receiver，不单独显示助力者——master 明确要求）。
  每行 = **勾选框**（供「开始助力」选范围）+ 角色名 + 已占槽位 `n/3` + 当前模式标签
  （自动分配的槽位用不同底色区分，与手动指定一眼可分）。
- **右：选中 receiver 的 3 个槽位**。点某个槽 → **带搜索的下拉列表**（naive-ui `n-select filterable`），
- 候选 **只列 `assistPool` 内的角色**（master 已确认）；已被别的槽占用的会**禁用并标注「已用于 XXX」**。
  若想要的角色不在池内 → 提示「请先在批量日常页把它设为助力角色池」。
- **顶部状态按钮**：切换该 receiver 的 `manual` / `auto`。
- **顶部动作**：`自动分配`（见 §5）、`开始助力`（见 §6）。

**不显示爬塔进度**（master 已确认，保持页面轻量）——所以本页不需要为每个角色建连接查 `EvoTowerInfoResp`，
手动指定完全依赖 master 自己的判断。

## 5. 自动分配规则

对**所有 `mode === "auto"` 的 receiver**，填充其空槽位：

1. 候选 = `assistPool` 中**没有被任何槽位占用**的角色（已被占用的不会被抢）。
2. 排除 receiver **自己**（不能给自己助力）。
3. 排除本周期已进入 `usedInitiators` 的角色。
4. 从候选中**随机**取（master 说「随便安排」）。
5. 候选不足时：尽量填，**剩余空槽保留**并在报告里给出缺口
   （例：10 个自动接收角色需 30 个助力者，池内只剩 20 个 → 填 20、报缺 10）。
6. 分配结果**写回持久关系**（`slots`），这样下次打开页面还是它——关系本来就是持久的。

### 模式切换语义（master 已确认：**切换即清空**）

- **手动 → 自动**：**清空该 receiver 的 3 个槽**，完全交给自动分配。
- **自动 → 手动**：槽位保持自动分配的结果不动，允许逐个手工调整。
- ⚠️ 切到自动会丢掉已有的手动指定，切回去要重填——这是 master 明确选择的语义（干净优先）。

> 一个实现细节（**我按默认实现，若不合适请指出**）：自动模式下槽位**仍可点开手动覆盖**。
> 理由：自动分配本来就会跳过已占用的槽，允许覆盖不会破坏一致性；而"看得见却点不动"体验更差。
> 若希望严格只读，只需关掉槽位的点击处理。

## 6. 执行（开始助力）

**执行范围**：对**左列表中被勾选的 receiver** 执行（默认全选，可只勾几个分批跑 —— master 已确认）。

按周期缓存 + 逐条执行：

1. **取码**：对每个 receiver，用**它自己的连接**发 `evotower_getsharecode`（每周期缓存一次）。
2. **助力**：对每条已分配的 `(助力者, receiver)`，用**助力者的连接**发
   `evotower_acceptsharebycode { shareCode: receiver的码 }`。
3. **错误分流**（看 `err.code`，不匹配文案）：

   | code | 处理 |
   | --- | --- |
   | 成功 | 记入本周期已执行 |
   | `12200100` | 该助力者 → `usedInitiators`，从其它槽位移除并提示 |
   | `12200090` | 该 receiver → `fullReceivers`，该角色本周期不再尝试 |
   | 其它 | 仅报错，不写黑名单 |

4. **窗口闸门**：执行前先判断助力窗口是否开放（见 §6.1），关闭时直接拒绝并说明原因，
   **不要把窗口关闭失败记进黑名单**。

### 6.1 窗口判定（重要，容易写错）

```
活动周：周五 12:00 开 → 周四 24:00 关（共 6.5 天）
之后 周五 00:00 ~ 12:00 的 12 小时是「尾巴期」：只能使用道具 / 领奖励，战斗与助力已关闭
```

- **不能直接用 `isWeirdTowerActivityOpen`**（它按 `cyclePosition < 7 天` 算，**含尾巴期**，是超集）。
- 助力可用 = 当前是黑市周 **且** `(now - 周期起点) < 6.5 天`。

### 6.2 周期键

- **主用**：本地三周轮换算出的周期序号（锚点 `2025-12-12T12:00`，与 `WeirdTowerStatus.vue` 现有一致）。
- **旁证**：`EvoTowerInfoResp.evotower.taskMap` 的**最早日期键**（#13 时为 `260911`），记进日志用于确认两者同步滚动。

### 8.1 实现里的几个细节

- **卡片与批量页共享同一个 `useLocalStorage` ref**（`weirdTowerAssistPlan`），
  所以批量页点完按钮，卡片立刻跟着变；跨标签页也靠 storage 事件同步。
- 卡片用**排除法**记勾选（`excludedReceiverKeys`）：新加入的接受角色默认选中，删掉的自动消失，
  避免「选中集合」在关系变化后不收敛。
- 手动指定槽位时做**全局唯一搬迁**：把某助力者指给新槽位，会自动从它原来的槽位腾空。
- 执行分两阶段：**先取码**（每接受角色一条连接，按周期缓存）→ **再助力**（每助力者一条连接）。
  并发上限 2（卡内常量 `MAX_CONCURRENT_CONNECTIONS`）。
- 收到 `12200100` → 标记该助力者本周期用尽并**从所有槽位移除**；收到 `12200090` → 标记该接受角色本周期已满。
- 执行前检查**助力窗口**，关闭时直接拒绝且不写黑名单。
